# D1.3 – Hauptmenü und Kolonieverwaltung

> Ausführung: superpowers:executing-plans, TDD, unabhängige Abschlussprüfung.

**Spec:** ../../2026-10-28-D1.0-DATENINVENTAR-UND-SPEICHERVERTRAG.md
**Ziel:** Start immer im Menü; bestehende Saves sichtbar fortsetzen und verwalten.
**Architektur:** Native HTML-Oberfläche im bestehenden Stil, eigene Phaser-
Menüszene; WorldScene bekommt eine bereits erzeugte/geladene ColonySession.
Metadaten getrennt von großen Payloads in IndexedDB, Änderungen atomar und
unter exklusiver Koloniesperre. Kein neuer Spielmechanik-/Grafikumbau.

## Verbindliche Regeln

Letzte Kolonie vorausgewählt, Fortsetzen mit einem Klick; Neugründung mit Namen,
Umbenennen ohne ID-Wechsel, zuletzt gespielt zuerst. Tag/Ameisenzahl/letzter
Erfolg/Backupstatus sichtbar. Löschen nur nach Exportangebot und weiterer
Bestätigung; Abbruch/Exportfehler löscht nichts. Keine fremde Kolonie verändern.
Keine künstliche Kolonienanzahl; Liste in Abschnitten rendern. Kein automatisches
Laden/Zurücksetzen beschädigter Saves. Kein Backup-Restore oder Import (D1.4).

## Entscheidungen

Bestehende Farbe/Typografie und native Formulare wiederverwenden; keine externe
Designgenerierung, im Sinne des ausdrücklich sparsamen Arbeitsauftrags.
Arbeitsverzeichnis beibehalten und Quellstand unter /tmp sichern; kein Commit,
Push oder Branchwechsel. Technischer Dateiexport als validiertes JSON, Dateiname
bereinigt; keine neue Namenslängengrenze. Größenlimit vor dem Speichern entspricht
bereits bestehendem Parserlimit, damit kein unladbarer Save geschrieben wird.
IDB-Version2 ergänzt Metadaten/Präferenzen, übernimmt alte D1.1/2-Datensätze.

- [x] 1. Repository/Katalogverwaltung: Metadaten, letzte Auswahl, Umbenennen,
Export und revisionsgeprüftes Löschen. Tests zuerst rot.
- [x] 2. Menü und sichere Szenenwechsel: neue/geladene Sitzung, Weltbindung,
Aufräumen, Pause und Speichern beim Rückweg. Browserprüfungen zuerst rot.
- [x] 3. Abnahme: Reload ohne Simulationsstart, Fortsetzen, getrennte Kolonien,

Gesamttests, Build und unabhängige Codeprüfung.

## Prüffokus

Startobjekt-Duplikate, alte Rendererreferenzen, Schreibsperren beim Wechsel,
fehlgeschlagenes Speichern/Exportieren, Aktionen auf veralteten Listeneinträgen.
